# repos-control

Десктоп-панель контроля git-репозиториев (Tauri 2 + Rust + Vanilla JS).

Для каждого добавленного проекта показывает:

- текущую ветку;
- staged / unstaged / untracked изменения;
- unbushed: ahead / behind относительно upstream;
- генерацию commit-сообщения по диффу (сейчас LLM-заглушка);
- панель коммита на проект: stage/unstage/discard файлов, сохранение сообщения в `.git/COMMIT_EDITMSG`, коммит и push.

Git-операции: чтение (статус, дифф, ahead/behind) — библиотека `gix`; запись (stage/unstage/discard/commit/push) — `git2` (libgit2, без вызова `git.exe`).

## Как обновляется состояние

- **Кэша статуса нет.** Единственный источник правды — рабочее дерево и `.git`
  на диске. Кэш статуса в памяти означал, что UI до 10 секунд показывал
  состояние «до операции», и stage/commit/push выглядели как ничего не сделавшие.
- **Команды записи возвращают свежий статус** в том же ответе (`StatusSnapshot`):
  нажал → крутилка → готовые данные, один round-trip.
- **Все чтения статуса идут через `infra/status_hub.rs`**: ограничение параллелизма
  (4) плюс сериализация чтений одного проекта. У снапшота есть монотонный `seq`
  (номер чтения) — фронт применяет только максимальный, поэтому позднее
  завершившееся старое чтение не перерисовывает свежий статус.
- **Watcher не теряет события**: если перечитать статус нельзя (идёт запись или
  троттлинг), событие перевзводится в очередь, а не отбрасывается.
  Запись помечается в `infra/write_registry.rs` по пути проекта, поэтому запись
  в одном репозитории не блокирует обновление остальных.
- Автообновление: fs-watcher (debounce 1с, троттлинг 5с) + перечитывание при
  возврате фокуса в окно. Кнопка «Обновить» осталась как ручной фоллбэк.
- Промежуточных «правдоподобных» цифр в UI нет: пока операция идёт — крутилка,
  после — фактическое состояние из ответа; ошибка показывается баннером.


## Сборка и запуск

- `build.bat` — dev-сборка и запуск GUI (без установщика).
- `run_check.bat` — `cargo check` через обёртку (MSVC-init + сброс sccache).

См. `AGENTS.md` — обязательные правила проекта.
